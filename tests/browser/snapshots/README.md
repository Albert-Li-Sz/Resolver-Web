# 浏览器画面基线

固定环境：Playwright **1.64.1**、Chromium、`linux/arm64`、官方 Noble 镜像，镜像摘要见 `.github/workflows/browser.yml`。本机和 CI 必须使用相同系统、架构与浏览器；不要用 macOS 截图替换 Linux 基线。

- 11 种原生模板 × 中英两种语言 × 1080p / 1440p / 2160p：66 张。
- 新待机画面 × 中英 × 三种分辨率：6 张。
- 榜单和待机 × 中英 × 32:9 LED / 方形：8 张。
- 375×812 移动管理页：1 张。
- 非空队列（待判、通过、未通过）× 中英 × 三种分辨率：6 张。
- 中文长队名的榜单和队伍介绍 × 三种分辨率：6 张。
- Live 单路 / 双路 / 四路 × 三种分辨率的固定视频帧：9 张。
- 比赛已结束的榜单表头 × 中英 × 三种分辨率：6 张。

合计 **108 张**。Live 用例固定在比赛结束状态，单独锁定软件合成和整像素字体定位参数（`live-visual.spec.ts`）；原生模板保持改造前的启动参数。固定视频是本地生成的 1080p / 30fps 静态色条，每帧独立编码，解码帧哈希相同；截图前同时等待视频就绪和占位层退出。生成方式见 [媒体夹具说明](../media/README.md)。

使用固定赛事、时间、动画阶段、图片与字体；中文测试还检查随项目打包的 FontFace 确实加载。每个像素必须一致（`threshold: 0`、`maxDiffPixels: 0`）。移动管理页只模拟稳定状态，不替代 `workflows.spec.ts` 的真实服务流程。

英文 33 张原生模板基线先在本次中文化之前的渲染器上保存，然后使用新渲染器逐像素对照；原始源码和素材哈希记录在 `provenance.json`。它证明本次功能没有改变原有 Web 画面，不代表浏览器与官方 Java 抗锯齿完全一致。中文及新增画面经过目视检查后保存。

日常验证：在固定镜像内执行 `npm run test:visual`。CI 不更新基线，失败时上传实际图、差异图和 trace。

只有预期画面发生变化时，才对明确的单个测试使用 `npx playwright test --grep '测试名' --update-snapshots`。先检查 actual/diff，再目视审核完整图，最后将 PNG 与修改理由一起提交；不要为了通过失败测试批量重录。执行环境与命令参见 [部署和开发说明](../../../doc/PLATFORM.md)。
