# 赛事制作台

四个入口：Resolver（滚榜）、Live（导播）、PresentationAdmin（多屏管理）、Presentations（展示屏）。管理端使用同一管理员密码，用户名 `admin`；首页、展示屏和只读输出可直接打开。

## 部署

安装 Docker Compose，在源码目录执行：

```bash
cp deploy/platform.env.example .env
# 设置管理员密码、随机媒体内部密钥、服务器场馆局域网 IP。
docker compose --env-file .env -f compose.platform.yaml up -d --build
```

访问 `http://服务器IP:4173/`。媒体需要场馆设备可访问 TCP 8554、1935、8888、8889、8189，UDP 8890、8189。WebRTC 默认使用场馆 IP；无需公网穿透或 TURN。

数据保存在 `resolver-data` 命名卷。升级需保留原 Compose 项目名与命名卷；不要使用 `down -v`。从 v1.3.0 升级时保留管理员密码，并补充 `MEDIA_INTERNAL_KEY`、`MEDIA_PUBLIC_HOST`；发布包的镜像覆盖字段为 `RESOLVER_IMAGE` 和 `MEDIA_WORKER_IMAGE`。已有单服务部署的 Resolver 数据目录可继续使用，新平台数据单独存放在 `data/platform/`。媒体控制接口和 FFmpeg 工作服务只在容器网络内开放，不挂载 Docker socket。

## Live

1. 打开“赛事接入”，创建工作区或上传 NDJSON。工作区可保存多份赛事，同时连接一个实时赛事。
2. 实时来源可填写 Contest API 根地址与比赛 ID，或完整持续事件流地址。填写 Basic 用户名/密码或 Bearer Token；场馆内网来源需勾选允许内网访问。
3. “保存并连接”开始持续接收；“测试连接”检查状态；“停止连接”保留已经收到的数据。切换来源时清空原实时数据，Resolver 快照不变。
4. 打开“媒体来源”，为队伍填写摄像头、桌面、音频地址，或生成带发布凭据的 RTSP/RTMP/SRT 地址。来源凭据仅在管理端保存。批量导入使用 JSON 数组。
5. 原始编码无法在浏览器播放时启用兼容转码。正常来源优先转发，浏览器优先 WebRTC，必要时回退 HLS；HLS 延迟通常更高。
6. 在“赛事素材”设置赛事 Logo、队伍校徽和照片；上传的本机素材与实时事件分开保存。
7. 在“导播控制”选择单队伍、双队伍或四分屏，调整叠加组件。修改只作用于预览；点击“切换到正式画面”后才上屏。可保存布局预设。
8. 在“输出设置”复制正式画面或透明叠加链接。OBS 添加“浏览器”来源，设置 1920×1080、2560×1440 或 3840×2160。链接中的只读凭据可重新生成，旧链接随后失效。
9. 默认保留封榜。仅在允许公开结果后启用“公开解榜”；这一设置不改变已经生成的 Resolver 滚榜进度。

## 多屏展示

1. 在展示电脑打开 `/presentations/`，得到 10 分钟有效的 8 位链接码。
2. 管理电脑进入 PresentationAdmin，输入码和屏幕名称，完成长期绑定。
3. 选择一个或多个屏幕，编排节目、每项时长、循环和转场，然后下发节目单。
4. 管理端可分组、多选、黑屏、恢复、暂停、继续及前后切换；缩略图来自展示端实际画面。
5. 选择单屏的“编辑节目单”可载入正在运行的节目后修改；已保存的节目单可重复下发。
6. 首次在屏幕上点击“启用全屏与声音”。浏览器全屏和声音需要本机交互，管理员下发内容不会绕过浏览器限制。
7. 页面地址包含屏幕 ID，本浏览器保存独立身份。使用“新建独立展示屏”可在同一浏览器创建另一块屏幕；保存各屏幕地址，刷新与重启仍恢复对应屏幕。
8. 页面保持打开时，离线保留当前画面，已缓存节目单继续运行，视频源断开时显示占位；重新连接后应用最新状态，不重放旧命令。解除绑定会重新显示短码。

节目包括实时榜单、领先队伍榜、比赛时钟、倒计时、判题队列、首解、队伍介绍、赛事 Logo、图片轮播、公告、校准，以及 Resolver / Live 输出。可选择 1080p、2K、4K 和 LED 比例。

## Resolver 兼容

原有五页配置流程迁至 `/resolver/`；旧页面链接自动跳转。原 `/view`、主持与观众链接、浏览器设置、服务器预设、奖项和恢复数据继续使用。

在 Resolver 的“共享赛事工作区”选择赛事并点击“创建滚榜快照”。该快照独立保存；实时赛事更新或切换工作区不会改变已准备的滚榜。覆盖当前赛事仍需确认，并可撤销载入。

## 开发与验收

```bash
npm ci
npm run build
npm start
npm run check
npm test
```

媒体功能使用完整 Compose 部署；仅 `npm start` 仍可使用赛事、Resolver、配对、多屏模板和无视频的导播输出。媒体未配置时返回明确错误，不用演示视频代替真实来源。

自动测试涵盖旧 Resolver 回归、公开封榜过滤、事件去重/重判/删除、来源切换竞争、身份权限、配对过期、持久化、节目同步及旧版本路由。现场验收还需记录测试硬件，检查 10 屏及 4 路 1080p、OBS 接入、网络断开与各服务重启。

本次本地验收结果、硬件和测量边界见 [PLATFORM-VALIDATION.md](PLATFORM-VALIDATION.md)。旧的《使用指南》PDF 仅介绍 Resolver v1.3.0，四模块操作以本指南为准。
