# 赛事制作台

四个入口：Resolver（滚榜）、Live（导播）、PresentationAdmin（多屏管理）、Presentations（展示屏）。管理端可配置统一管理员密码，设置后用户名为 `admin`；开放策略下密码留空可直接访问。首页、展示屏和只读输出可直接打开。

## 部署

快速安装、自动生成密钥及后续一键更新见 [一键安装与更新](INSTALL.md)。下面是手动 Compose 部署方式。

安装 Docker Compose，在源码目录执行：

```bash
cp deploy/platform.env.example .env
# 按需设置管理员密码，填写随机媒体内部密钥。
docker compose --env-file .env -f compose.platform.yaml pull
docker compose --env-file .env -f compose.platform.yaml up -d --no-build
```

默认监听 `0.0.0.0:4173`，可通过任意本机 IP 或域名访问。网络及安全策略由部署者配置，详见 [网络配置](NETWORK.md)。媒体需要场馆设备可访问 TCP 8554、1935、8888、8889、8189，UDP 8890、8189。WebRTC 默认使用场馆 IP；无需公网穿透或 TURN。

默认镜像为 `ghcr.io/albert-li-sz/resolver-web:main` 与 `ghcr.io/albert-li-sz/resolver-web-media-worker:main`，均支持 `linux/amd64`、`linux/arm64`。这是主分支的场馆验收版；OBS 与真实场馆验收完成前，稳定版 `latest` 保持 v1.3.0。固定部署时，将 `.env` 中两个镜像的标签同时改为 `sha-完整提交号`，或使用构建产物 `image-digests` 中的摘要。升级旧 `.env` 时补上这两个镜像字段，否则源码 Compose 会继续使用本地镜像名。需要源码构建时执行 `up -d --build`。

镜像通过 GitHub Actions 的 **Release containers → Run workflow → main** 手动构建。每次先通过 Node 22/24、页面、像素、真实媒体测试，再在两种原生架构上构建应用和媒体镜像，验证启动及重启，匿名检查 GHCR 后更新 `main`。提交号标签用于固定部署；此流程不创建稳定版本或改动 `latest`。GitHub 版本标签发布流程继续用于正式版本。

数据保存在 `resolver-data` 命名卷。升级需保留原 Compose 项目名与命名卷；不要使用 `down -v`。从 v1.3.0 升级时保留管理员密码，并补充 `MEDIA_INTERNAL_KEY`；发布包的镜像覆盖字段为 `RESOLVER_IMAGE` 和 `MEDIA_WORKER_IMAGE`。已有单服务部署的 Resolver 数据目录可继续使用，新平台数据单独存放在 `data/platform/`。媒体控制接口和 FFmpeg 工作服务只在容器网络内开放，不挂载 Docker socket。

管理界面采用 Ollama 的白色、细边框和圆角控件风格。Live 节目画面使用原版 Live-v3 组件，展示模板按 ICPC Tools v2.6.1331 的字体、坐标与绘制规则实现。

## 赛事中心

在 `/contest/` 创建赛事，选择 Contest API 根地址与比赛 ID，或持续 NDJSON 地址；认证方式可选无认证、Basic 或 Bearer。默认允许内网、回环和任意域名来源；只有启用 `restricted` 网络策略时才显示允许内网的选项。“测试填写内容”无需先保存。

新建或导入赛事后，点击“切换当前赛事”才会全端生效。编辑其他赛事不会切换正在播放的赛事；当前赛事的连接保存后立即重连。“停止连接”保留地址、凭据和已有数据，“重新连接”继续接收。每个实时赛事共用服务端连接，管理员换页面或新开展示屏无需再次配置。

“展示与素材”统一设置大屏语言、赛事 Logo、学校校徽和队伍照片，未匹配到学校时使用 ICPC Logo；“队伍媒体”设置摄像头、桌面、音频及备用来源，支持批量导入。视频仅按需打开，同一来源共享网关转发；在 Live 选择备用源只修改预览，确认后再切换正式画面。源凭据不会下发到观众和展示端。

新赛事的大屏原生模板默认简体中文，旧赛事保持英文；在“展示与素材 → 大屏模板语言”统一切换。模板缩略图和实际展示同时更新，队名、学校名、题号与自定义公告保留原文。中文字体及许可证随应用提供，无需连接外部字体服务。Live、Resolver 原有画面的固定文案保持原样。

默认执行封榜规则。“公开解榜”影响实时榜单、首解、通知及其他公开数据；不会推进 Resolver。切换当前赛事会清空旧赛事队伍和媒体引用及临时队列，保留布局与节目类型。更换同一工作区的 CCS 地址或比赛 ID 时重新执行封榜，并清理旧赛事画面引用；仅修改凭据或停止、恢复连接会保留当前赛事状态。

公开或恢复封榜、切换当前赛事、替换当前数据源、解除绑定、更换输出链接，以及移除或替换正式节目引用的媒体，都先显示影响范围。公开解榜还需勾选确认公开判题。取消、Escape 或关闭弹窗均不执行操作；提交期间不能重复点击。其他管理员改变相关控制状态时会提示刷新，实时判题与健康上报不会使确认失效。

## Live

1. 在“导播控制”搜索队伍，选择单队伍、双队伍或四分屏；队伍关联的摄像头与桌面可自动组成画中画。
2. 调整组件、字幕、图片和音量，预览默认静音。修改预览不会上屏，点击“切换到正式画面”后才切换。
3. 布局可保存为预设；载入后“更新预设”修改原项，“另存为”创建新项。坐标调整放在组件的“位置”中。
4. 在“输出设置”分别保存正式画面与透明叠加的分辨率、比例、安全边距及区域；复制链接至 OBS 浏览器源。默认 2K，支持 1080p / 4K。
5. OBS 链接包含 `clean=1`，始终为纯画面。重新生成链接会使旧链接失效，需要更新 OBS。

“进入待机”立即让正式输出及 Live 适配屏显示赛事 Logo 与“请稍候 / Please stand by”，停止正式端视频和声音，并清空透明叠加；预览仍可编辑。“恢复正式节目”恢复当前正式场景，“回切上一正式节目”使用上一场景并消耗这条记录，均不覆盖预览草稿。待机不会覆盖回切记录；切换赛事或替换 CCS 数据源会清除旧记录。场景、待机和回切记录在服务重启后保留。

同一输出页面已启用的声音会在恢复后保留；刷新页面后仍需遵守浏览器的声音限制。OBS 继续负责最终录制与平台推流。

协议和编码兼容由媒体网关处理；优先 WebRTC，必要时回退 HLS。HLS 延迟通常更高。浏览器不支持原编码时可启用兼容转码。

重命名来源不会重新拉流；修改连接参数会立即重连。移除来源会停止对应播放器、释放网关任务并撤销播放凭据，固定引用显示占位画面。独立音轨不会因普通榜单更新而重新连接。

## 多屏展示

1. 展示电脑打开 `/presentations/`，生成 10 分钟有效的 8 位链接码；在 PresentationAdmin 点击“连接展示屏”并命名。
2. 左侧选择屏幕或分组，中间选择带缩略图的模板，在右侧填写属性，再点击“立即上屏”。
3. 轮播时把模板加入节目单，调整顺序、单项时长、转场和循环，再点击底部“下发节目单”。保存后的节目单支持原位更新与另存为。
4. 底部操作栏提供黑屏、恢复画面、暂停、继续、上一项、下一项，以及待机、恢复节目和回切上一节目。屏幕卡片显示实际回传画面、执行状态与健康状态。
5. 在“屏幕设置”调整名称、分组和输出规格；多个屏幕可批量配置，各屏幕规格独立保存。
6. 展示电脑本机分别点击“全屏”和“启用声音”。隐藏控制栏后按 **H** 或点击右上角透明热区恢复；刷新、重连及节目切换保留隐藏状态。
7. 同一浏览器可通过“新建屏幕”创建独立身份，保存各自地址。离线时保留画面和已缓存节目单，重连应用最新状态；解除绑定后重新生成链接码。

模板包括实时榜单、领先队伍榜、比赛时钟、倒计时、判题队列、首解、队伍介绍、赛事 Logo、图片轮播、公告、校准，以及 Resolver / Live 输出适配器。管理端不会绕过浏览器的全屏和声音限制。

大屏应急操作只影响已选屏幕，沿用 750ms 预约同步并直接切换。每块屏幕仅保留上一套实际生效节目的记录；尚未上屏的预约目标不会替代上一节目。退出待机、回切上一节目单都沿原时间轴继续，原本暂停的节目保持暂停。比赛时钟和榜单读取最新公开数据。黑屏和输出规格独立保存，待机恢复或节目回切不会解除黑屏，需要另点“恢复画面”。

## 健康监测

屏幕卡片与 Live 的“输出与媒体状态”显示在线、渲染、回传画面及实际媒体协议、分辨率、帧率、重连和转码状态。健康数据仅管理员可读，不包含源地址、凭据或原始 FFmpeg 命令。告警不会自动切换节目。

| 指标 | 判定 |
|---|---|
| 在线 | 每 5 秒心跳，15 秒未收到则离线。 |
| 渲染 | 在线前台页面上报渲染循环超过 5 秒未推进则异常；初次加载有 15 秒宽限期。 |
| 视频 | 沿用 6 秒断帧和自动重连；连接失败可回退 HLS。 |
| 实际回传 | 超过 20 秒未更新提示陈旧，捕获失败单独标识。 |
| 兼容 | 后台页面、静态画面和未提供指标的旧客户端分别标识。 |

独立正式输出与透明叠加也会回报健康状态；`clean=1` 画面中始终不出现诊断面板或管理通知。

## Resolver

原五页配置、主持与观众链接、`/view`、奖项、预设及滚榜恢复继续有效。

赛后选择已配置的赛事，点击“从 CCS 获取并载入”，也可直接上传 NDJSON。CCS 账号必须能读取完整判题；公共封榜流缺少最终判题时不能用于完整滚榜。获取成功后提供 NDJSON 下载备份，载入的赛事和素材成为独立快照；后续实时事件、赛事切换和公共素材修改不会覆盖它。

标准 Contest API 通过有限的资源集合获取赛后快照，并二次检查提交与判题是否变化，因此无需等待 CCS 公开解榜或关闭事件流；保留已知封榜时长。持续 NDJSON 来源使用结束状态与完整判题检查，支持 `end_of_updates` 标记。获取失败、取消或校验未完成时保留原滚榜；可以重试或手动上传。

赛事中心与 Resolver 的封榜还原、奖项和滚榜节奏分别按用途管理；本次滚榜的素材修改不会写回公共赛事。

## 开发与验收

```bash
npm ci
npm run build
npm start
npm run check
npm test
```

页面与像素回归使用锁定的 Playwright 1.64.1 和 Linux arm64 镜像；与 CI 使用同一架构，避免系统字体及栅格化差异：

```bash
docker run --rm --init --ipc=host --platform linux/arm64 \
  -e CI=1 -v "$PWD:/app" -w /app \
  mcr.microsoft.com/playwright:v1.64.1-noble@sha256:47b510dd9230bf0b9bfc9b20102241e577ea7a99334ab4c3ca19f19770e9b8ea \
  npx playwright test
npm run test:media
```

分别运行时使用 `npm run test:e2e`、`npm run test:visual`；视觉命令需在上述固定镜像内执行。真实媒体测试自行启动隔离 Compose、合成发布流与浏览器，验证断流、恢复、HLS 回退、WebRTC 及声音恢复，结束后清理自己的容器；不使用现有赛事数据卷。失败截图、差异图和 trace 位于 `test-results/`。像素基线只在明确人工检查后更新，流程见 [浏览器基线说明](../tests/browser/snapshots/README.md)。普通 CI 与容器发布均接入这些门禁。

媒体功能使用完整 Compose 部署；仅 `npm start` 仍可使用赛事、Resolver、配对、多屏模板和无视频的导播输出。媒体未配置时返回明确错误，不用演示视频代替真实来源。

自动测试涵盖旧 Resolver 回归、公开封榜过滤、事件去重/重判/删除、来源切换竞争、身份权限、配对过期、持久化、节目同步及旧版本路由。现场验收还需记录测试硬件，检查 10 屏及 4 路 1080p、OBS 接入、网络断开与各服务重启。

DOMjudge、Hydro + CCS API 接入与完整操作步骤见 [图文说明书](使用指南.md)及其 [PDF](使用指南.pdf)。本轮现场保护与中文化结果见 [ONSITE-VALIDATION.md](ONSITE-VALIDATION.md)，共享赛事与 UI 验收见 [OLLAMA-VALIDATION.md](OLLAMA-VALIDATION.md)，此前平台基线见 [PLATFORM-VALIDATION.md](PLATFORM-VALIDATION.md)。
